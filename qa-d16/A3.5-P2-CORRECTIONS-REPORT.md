## 4. Malformed configuration compatibility decision

Pre-P2 semantics were inspected in `git show HEAD:app/engine/anomaly/trends.py`:

* the five finding gates were read raw and compared numerically
  (`:268-269, 286-295`): a string, `None` or numeric string raised `TypeError`;
* `trend_finding_consecutive` was also compared raw (`:290`): same exception;
* `zscore_threshold` used `float(...)` (`:388-389`): numeric strings were
  accepted; bad text raised `ValueError`, `None` raised `TypeError`;
* other trend settings already went through `resolve_trend_settings`, which
  records `invalid` and substitutes the default.

**Decision:** preserve those distinctions rather than silently defaulting.

| Input (explicit) | Legacy result | Corrected adapter |
|---|---|---|
| key absent | engine table default | same (`_legacy_gate` presence check) |
| valid int/float | used | used |
| numeric string on a finding gate | `TypeError` | `TypeError` (not coerced) |
| numeric string on Z | accepted by `float()` | accepted |
| invalid string on gate / persistence | `TypeError` | `TypeError` |
| invalid string on Z | `ValueError` | `ValueError` |
| `None` on gate / Z / persistence | `TypeError` | `TypeError` |
| non-finite float on gate/Z | accepted, comparison just never fired | accepted unchanged |
| non-finite persistence | no raise (comparison false) | **deliberate `ValueError`** — the settings plane would otherwise substitute 3 and could add a finding |
| malformed window/direction/etc. | recorded `invalid`, default | unchanged |

The adapter docstring now states exactly this and no longer claims “unchanged
results” for malformed input. Production stored configuration cannot reach the
change: `AppConfig.value` is `Column(Float, nullable=False)`
(`app/models.py:662`) and the gates are AppConfig keys.

  `explain_layered`/the layered payload calls it once (`:3082`).

  the displayed value is unchanged for stored configuration; the default

  `severity.load_analysis_config` to raise and still gets

  stored `3.0`.
