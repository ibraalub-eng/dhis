## P3.3.1 — ConfidencePolicy

### Implemented contract

`app/engine/confidence_policy.py` provides:

* `CONFIDENCE_POLICY_VERSION = "1.0.0"`;
* ordered `WEIGHT_KEYS` and immutable `DEFAULT_WEIGHTS` (`MappingProxyType`);
* literal defaults `0.55/0.10/0.10/0.10/0.15`, cutoffs `80/50/25`, raw Z `2.5`;
* frozen `ConfidencePolicy` with `defaults()`, `weight_for()`, and
  `as_weight_mapping()`;
* `validate_weight_values()` for a complete set;
* `validate_weight_update(payload, current)` for a partial PUT: merges against
  the effective policy, requires at least one known key, rejects unknown keys,
  and returns the complete five-value mapping without mutating `current`;
* `WEIGHT_SUM_TOLERANCE = Decimal("0.01")` with strict `<` behavior.

Validation rejects booleans, strings, non-numeric values, `NaN`, infinities,
oversized non-representable integers, negatives, missing keys, and unknown keys.
Weights are compared with `Decimal(str(value))`; values are stored/returned
without rounding or normalization. Exact `0.99` and `1.01` are rejected;
`0.9999999999999999` is accepted. `ConfidencePolicy` itself cannot be constructed
with an invalid weight total, and all nine scalar fields must be finite and
nonnegative. Cutoffs and raw Z are not clamped or rounded.

## Remaining issues

1. **No P3.3.2 integration.** The resolver does not yet produce the five weight
   entries, the snapshot does not yet identify confidence `1.0.0`, and the
   engine still reads the legacy global/table. This is intentional.
2. **Invalid legacy weight rows are not yet repaired.** `ConfidencePolicy`
   correctly refuses an out-of-tolerance total; P3.3.2 must catch that and apply
   its approved fallback/validation provenance rather than constructing an
   invalid policy.
3. **Duplicate `ConfidenceWeights` rows remain unresolved.** P3.3.2 owns
   lowest-id selection and conflict recording.
4. **No API or UI changes.** GET still creates a row; PUT still checks only the
   supplied subset; Diagnostics/Settings still show the legacy policy.
5. **No cutoff ordering rule was added.** The approved contract does not require
   one, and adding it would change existing configuration acceptance.
6. **Fixture size.** The complete 48-payload baseline is 257 KB; it is
   deterministic, contains no production rows or secrets, and is not regenerated
   during normal tests.
