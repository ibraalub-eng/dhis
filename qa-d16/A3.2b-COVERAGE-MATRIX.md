# A3.2b — Corrected Coverage Matrix and Counts

This file supersedes the matrix and counts in the A3.2 report. Classifications are **not** adjusted
to make totals agree; each change below is a correction of a counting or tracing error, with the
evidence stated.

---

## 1. What was wrong in A3.2

| A3.2 statement | Correct value | Cause |
|---|---|---|
| "consumed but not covered **18**" | **17** | double-counted one setting; see section 3 |
| "18 consumed keys still read the database directly" | **17** | same |
| `auto_disable` "writers: 2 paths" | **1 production writer** | "not seeded" was listed as if it were a writer; a seeder is an absence, not a writer |
| `auto_disable` "6 modules / 7 read sites" | **10 modules / 16 read sites / 18 dependency edges** | only direct reads of the setting were counted; the 9 callers of `get_disabled_indicator_ids` inherit the decision |
| "null/missing excluded from enabled values" | **false for the numerator** | `get_enabled_values_for_hospital_month` subtracts only *manual* disable; auto-disable changes the **denominator** and the confidence assessed list |
| `fdr_q` "unbounded" | correct, and additionally **uncaught** | `float(config.get("fdr_q", 0.05))` in `correlations`, called outside the `try` that wraps patterns |
| `pattern_min_support` invalid value | non-numeric raises, but is **contained** by `run_smart_analytics` around `detect_composite_patterns` (returns `[]`) | the wrap covers patterns only |

Nothing in the classification itself changed; only counts, readers and two mechanism descriptions.

## 3. Corrected counts, with the accounting

| Category | Count | Members |
|---|---|---|
| Settings audited | **19** | rows 1-19 above |
| Covered by the resolver | **0** | none of the 19 |
| Consumed and uncovered | **17** | 1-14, 17, 18, 19 |
| Seeded but unused | **2** | 15, 16 |
| Consumed but unseeded (dynamically defaulted) | **2** | 17, 18 |
| Seeded smart keys | **15** | 2-16 |
| Seeded **and** consumed | **13** | 2-14 |

Two categories overlap by construction, and the totals only reconcile when that is stated:

```
19 audited
  = 17 consumed-and-uncovered  + 2 seeded-but-unused
17 consumed
  = 13 seeded-smart-consumed + 2 unseeded-smart-consumed(17,18) + 2 SystemSetting(1,19)
15 seeded smart
  = 13 consumed + 2 dead (15,16)
 2 dynamically defaulted (17,18)  ⊂  17 consumed
```

The A3.2 "18" came from counting the 15 smart keys as consumed (including the 2 dead seeds) and
adding the 3 non-smart settings: `15 + 3 = 18`. The dead seeds are seeded but **not** consumed, so
the correct total is `13 + 2 + 2 = 17`.

## 4. Matrix maintenance rule

When A3.3 lands a plane, only the affected row's **Covered** and **Parity** columns change; the
counts in section 3 must be recomputed from the table, never edited by hand. A row may not be
marked "Parity = yes" until the differential suite in `A3.2b-PARITY-PLAN.md` passes for that key and
the consumer demonstrably reads the snapshot value.
