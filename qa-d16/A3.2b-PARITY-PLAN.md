# A3.2b — Parity Plan: proving "no behaviour change" before any consumer is switched

**Purpose:** define the exact evidence A3.3 must produce before a consumer stops reading the
database. This document is a plan; **no test here is claimed to have run**, except where section 6
records the design-phase tests that do run today.

Rule for the whole plan: **a snapshot may replace a database read only when the differential suite
in section 3 passes for that key on the same stored rows.** "The resolver returns the expected
default" is never sufficient - it proves the default, not parity.

---

## 1. The 13 parity conditions

| # | Condition | Evidence required | Failure means |
|---|---|---|---|
| 1 | Resolver value == current consumer value for **every valid stored configuration** | differential comparison over fixture matrix (section 2) for each key | the resolver parses differently |
| 2 | Missing setting preserves the current default | fixtures `F0`, `F4`; compare with the consumer's inline default | a default moved |
| 3 | Stored `false` / `0` keeps its meaning | `F2` (`false`), `F5` (`0`) for each gate; assert effective value is OFF, not the default | a zero/false was treated as absent |
| 4 | Coercion preserved (including odd coercions) | per-key "coercion" row of the spec; e.g. `int(min(v, n-1))`, `int()` truncation, raw weights | a value was normalised silently |
| 5 | No formula change | call both paths for the same month and compare `QualityScore` fields | formula drift |
| 6 | No severity-band change | `policy_fingerprint(sev_cfg)` equal before/after; stored `QualityAlert.severity` equal | bands moved |
| 7 | No peer-grouping change | `comparison_policy_from_snapshot` equal to `load_comparison_policy(db)`; peer counts identical | grouping moved |
| 8 | No indicator-eligibility change | `get_disabled_indicator_ids` set equality per (hospital, month, flag state) | eligibility moved |
| 9 | No completeness change | `compute_hospital_completeness` equality (both numerator and denominator) | denominator or numerator moved |
| 10 | No confidence change | `HospitalConfidenceResult` equality (assessed list + per-indicator confidence) | assessed list moved |
| 11 | No Smart Analytics output change | deep-compare `SmartAnalyticsResult` (anomalies, clusters, correlations, residuals, stratified, explanations, patterns, KPI, xgb) | smart output moved |
| 12 | No dashboard drift classification change | `attention` payload equality including the `months` field | drift moved |
| 13 | No existing API response contract change | response model field sets + JSON snapshot for the touched endpoints | contract drift |

## 2. Fixtures

All fixtures are **isolated temporary SQLite databases** (the pattern already used by
`tests/test_a3_2_config_coverage.py`): no production database, no migration, no seed script.

| Fixture | Contents | Purpose |
|---|---|---|
| `F0` empty | no `SystemSetting`, no `AppConfig`, an indicator catalog with one hospital | defaults, absence semantics |
| `F1` full | every audited key at its seeded/document value, 3 hospitals x 3 months with a mix of non-null, null and missing indicator rows | the "normal" path |
| `F2` explicit-false | `auto_disable_null_indicators="false"`, `smart_enabled=0`, weights `0` | false/zero must not be replaced by defaults |
| `F3` text-noise | `"TRUE"`, `"True"`, `"true "`, `"yes"`, `"1"` for the flag; `"3.6"`, `"abc"`, `"9"` for drift | parse parity, including the values that read as OFF |
| `F4` partial | only a subset of keys present (e.g. `smart_contamination` set, `smart_lof_neighbors` absent) | per-key independence; one row must not imply another |
| `F5` zero/edge | `contamination=0.05`, `lof_neighbors=2`, `dbscan_min_samples=1`, weights `0,0,0,0`, `fdr_q=0.05`, `pattern_min_support=0.2` | boundary behaviour, still no analytical change |

`F1` must include the three tie cases that decide the flag: a non-null row, an explicit null row,
and an indicator with no row at all. Without all three, a parity run can pass while the eligibility
rule is wrong.

## 3. Differential strategy

### 3.1 Harness shape (test-only)

```python
def both_paths(fixture, hospital_id, month):
    """Legacy path and snapshot path over the SAME rows, same session."""
    legacy = {
        "disabled_ids": legacy_get_disabled_indicator_ids(session, hospital_id, month),
        "required_ids": legacy_get_required_indicator_ids(session, hospital_id, month),
        "completeness": legacy_compute_hospital_completeness(session, hospital_id, month),
        "confidence": legacy_confidence(session, hospital_id, month),
    }
    snapshot = load_policy_snapshot(session)
    proposed = {
        "disabled_ids": get_disabled_indicator_ids(..., auto_disable_null=flags),
        ...
    }
    assert proposed == legacy
```

The legacy path is **the current function, unmodified**, kept callable during the transition. This
is why A3.3 step 2 introduces the parameter *before* the reads move: it lets the old and new
evaluation coexist in one process, on one session, over identical rows.

### 3.2 Comparison points, per setting

| Setting | Exact comparison point |
|---|---|
| `auto_disable_null_indicators` | ordered list equality of `get_disabled_indicator_ids`; set equality of `get_required_indicator_ids`; float equality of `compute_hospital_completeness`; deep equality of `HospitalConfidenceResult` |
| `alerts.auto_scan` | the boolean `_maybe_auto_scan_quality_alerts` acts on, plus "scan called / not called" via a spy |
| `anomaly_drift_months` | `get_anomaly_settings()["anomaly_drift_months"]` int equality; `attention` payload drift rows equality including `months` |
| `smart.enabled` / `smart.xgboost_enabled` / `smart.shap_enabled` | which of `anomalies / clustering / patterns / explanations / xgb_predictions` are empty, per gate combination (4 combinations, not 1) |
| `smart.contamination`, `smart.lof_neighbors` | anomaly list equality, including `score` within `1e-12` and identical `severity` |
| `smart.dbscan_eps`, `smart.dbscan_min_samples` | cluster label list + `n_clusters` + silhouette within `1e-12` |
| `smart.threshold_green` / `_yellow` | severity string per hospital |
| ensemble weights | raw ensemble vector before normalisation is not exposed; compare final `score` within `1e-12` for the ratio-equivalent pair `(0.35,0.3,0.2,0.15)` and `(0.7,0.6,0.4,0.3)` - they must match exactly, proving ratio semantics |
| `fdr_q` | set of significant correlation pairs |
| `pattern_min_support` | set of pattern item-sets + supports; also the effective value derived for `n=17` (adaptive) and a stored `0.2` |

### 3.3 Numerical tolerance policy

* Scores, weights, eps, contamination: `abs(a-b) <= 1e-12` (deterministic sklearn with fixed
  `random_state=42`).
* With `random_state` absent anywhere, use `<= 1e-9` and record why.
* Any tolerance increase after the fact is a parity failure, not a test fix.

## 5. Regression risks

| Risk | Likelihood | Mitigation |
|---|---|---|
| A call site silently keeps reading the DB and diverges from the passed value | **high** (16 edges today) | required keyword-only parameter (no default) so a missed site is a `TypeError`; a source-scan test that asserts the call-site inventory |
| `get_required_indicator_ids` resolves the flag twice (once itself, once for `get_disabled`) | medium | pass the bool through both; test P-02 compares denominator, not just the flag |
| Bulk hoisting changes cache behaviour | medium | P-31 with a mutation spy |
| Snapshot resolved but consumer keeps `get_config_dict` (the `rules`/`ml` pattern) | **high** - already true | parity tests must exercise the *consumer's* value, not the snapshot's; the A3.3 report must state which categories are still read per hospital |
| Smart key seeded but unconsumed, or consumed but unseeded | certain today | P3 decision; spec table is the single list |
| Floating-point drift in ensemble/clustering | low | fixed seeds, `1e-12`, ratio test P-20 |
| Digest scope accidentally includes a dashboard key | medium | P-12 and a test asserting `analysis` digest is invariant to drift |
| Error-path change (P1) masking a configuration outage as a zero | low after P1 | P-05 asserts explicit `configuration_unavailable`, never a fabricated score |
| Test fixtures drift from production defaults | medium | fixtures built from the spec table, and a test asserting the spec defaults equal the seed registry |

## 6. Design-phase tests that do run today

`tests/test_a3_2b_policy_boundaries.py` (read-only; no production code touched) pins the facts the
plan depends on:

1. the `get_disabled_indicator_ids` / `_is_auto_disable_null` call-site inventory (so a new reader
   cannot appear unnoticed);
2. `run_full_analysis`'s snapshot parameter and the absence of any caller passing `policy=`;
3. `_compute_full_analysis`'s five remaining `get_config_dict` categories;
4. the two silent `False` fallbacks (`dashboard`, `confidence`) vs. the raising paths;
5. the double decision in confidence (disabled set passed in *and* the flag re-read);
6. `alerts.auto_scan` resolved but dropped by `alerts_config_from_snapshot` and re-read by
   `_maybe_auto_scan_quality_alerts`;
7. the digest contract: `rules.hash` participates, `rules.updated_at` does not;
8. `snapshot_provenance()` exposes the digest used for future association.

These are contract pins, not parity proofs. They make the *absence* of integration explicit and
give A3.3 a red test the moment a boundary moves.

## 7. Stop conditions for A3.3 (inherited and sharpened)

Stop and report **without** switching a consumer if:

1. any differential case in section 4 fails and the fix would change an analytical value;
2. a call site cannot receive the flag without changing its public signature in a way that breaks
   an existing API response (contract condition 13);
3. bulk hoisting is proven unsafe (a path resolves configuration mid-batch by design);
4. preserving `pattern_min_support`'s adaptive default requires a second resolution point;
5. a digest association requires a schema change in the same step (split it out);
6. the smart plane cannot be resolved without also replacing `_load_config` (that replacement is a
   separate, parity-tested step);
7. `auto_disable`'s failure-policy unification (P1) is not approved - steps 4+ must not proceed.

Do not claim consumer parity on the strength of a default-value test, a single fixture, or a green
run of the existing suite. Parity is the differential suite over `F1`-`F5` with the consumer's own
output compared.
