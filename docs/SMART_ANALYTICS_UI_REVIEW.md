## 2. المشكلات — التشخيص

### 2.1 ازدحام المعلومات (أهم مشكلة)
- المستخدم (مدير جودة / صانع قرار صحي) يواجه **17 قسماً دفعة واحدة** بمصطلحات تقنية كثيفة: SHAP، XGBoost، Walk-Forward، O/E، Apriori/Lift، Mahalanobis، Isolation Forest، Choropleth. لا يوجد أي تسلسل هرمي بصري: «الشذوذ الإقليمي» (تحليل متقدم) له نفس الوزن البصري لـ«مستشفيات حرجة» (قرار عاجل).
- المحتوى الأهم للقرار (الإنذار المبكر §14، المستشفيات الحرجة) **مدفون في منتصف الصفحة**، بينما تتصدرها «المنهجية» المفتوحة افتراضياً.
- زر «تحديث» + شريط تحميل + نص حالة + Overlay — ثلاث آليات حالة في آنٍ واحد.

### 2.2 تكرار المحتوى (Redundancy)
| الظاهرة | الأماكن |
|---------|---------|
| توزيع الشذوذ | بطاقة KPI 1 + الدونات + الهيستوجرام + جدول الشذوذ |
| أهمية العوامل / SHAP | بطاقة KPI 3 + «أهمية العوامل» + Global FI في XGBoost + Waterfall في مودال المستشفى |
| الارتباط | Heatmap + العلاقات المتأخرة + ارتباطات المحافظات المتقاطعة |
| XGBoost | رسم «فعلي/متوقع» في الصف الملخص + قسم تنبؤات XGBoost كاملاً + Walk-Forward |
| منهجية الشرح | قسم «كيف تُحسب» المفتوح + صناديق «كيف تم تحديد» داخل كل مودال KPI + مودال المستشفى + التقرير |
| منسّق المؤشر نفسه | 3 قوائم منسدلة متطابقة (البواقي / أهمية العوامل / الطبقية) بنفس الخيارات الثلاثة |
| «تجميع المستشفيات» | رسم العنقودات + ملفات العنقودات + «مستشفيات سليمة» (كلها تصنيفات للمجموعة نفسها) |

### 2.3 الأداء
- **15–18 رسم Plotly تُرسم فوراً** على كل تغيير شهر حتى لو كانت خارج مجال الرؤية (لا يوجد `IntersectionObserver` ولا Lazy-render).
- رسم الخط الزمني (ارتفاع 460px + إطارات حركة لكل الأشهر × كل المستشفيات) يُبنى حتى لو لم يمر المستخدم عليه.
- **طلب مكرر**: `updateHospitalList()` يعيد جلب `/smart/overview/{month}` بعد أن جلبه `loadSmartData()` قبل لحظات — نفس الحمولة تُنقل مرتين.
- ترتيب الرسم يعتمد على **`setTimeout(100)` ثم `setTimeout(300)`** — رقعة توقيت هشة بدل تسلسل حقيقي؛ مع شبكة بطيئة يظهر القسم مكتملاً ثم يُعاد رسمه.
- قسم «الاستخبارات الإقليمية» وحده يحتوي ~10 أدوات (KPI إقليمية، رسم وفيات، رسم ولادات/وفيات، جدول وفيات، O/E، خطر، شذوذ، تفسير، ترتيب، اتجاهات) — لوحة كاملة داخل لوحة.

### 2.4 الصيانة والاتساق
- **أنماط inline في كل مكان** (في HTML وفي كل دالة `render` تقريباً) بدل فئات CSS قابلة لإعادة الاستخدام — تغيير لون/حجم واحد يتطلب تعديل عشرات المواضع، والتخطيط غير متجاوب تلقائياً مع شاشات الجوال لأن شبكات التبويب `grid-template-columns: repeat(4,1fr)` مثلاً مكتوبة inline ولا تلتقط `@media` الموجودة في `styles.css`.
- `smart-analytics.js` بلا تقسيم وحداتي؛ كل شيء في ملف واحد 2600+ سطر.
- تكرار دالة `_smartEscapeHtml` مرتين في الملف نفسه (سطر 669 و2265).
- بعض النصوص بها أخطاء إملائية (مثل «المتأضعة» في مودال العوامل، «المتوسطقة» في مودال حالة الشهر).
- وجود `duplicate` في الحالة: قسم «كيف تحسب هذه الدرجة؟» في مودال المستشفى يقول إنها تُحسب بمقارنة «جيرانه الأقرب» بينما المنهجية العامة تذكر 4 محركات — رسالتان مختلفتان.

### 2.5 إمكانية الوصول (Accessibility)
- أزرار كثيرة `div` مع `onclick` بلا `role="button"` ولا `aria-label`.
- المودالات بلا `role="dialog"`/`aria-modal` ولا قفل تركيز (focus trap) ولا إغلاق بمفتاح Escape.
- التلميحات عبر `title` فقط (غير متاح للوحة المفاتيح/قارئات الشاشة).
- تباين ألوان منخفض في نصوص صغيرة (0.65rem رمادي #aaa) على خلفيات فاتحة.

## 3. تدفق البيانات الحالي (لكل تغيير شهر)

```
تغيير الشهر
 ├─ GET /smart/overview/{month}          ← الحمولة الرئيسية (كل النتائج)
 │     (يحتوي: kpi, geo, clustering, correlations, residuals,
 │      patterns, anomalies, explanations, xgboost, stratified,
 │      lag_analysis, early_warnings, healthy_hospitals)
 ├─ GET /smart/overview/{month}          ← مكرر! (updateHospitalList)
 ├─ GET /smart/governorate-analysis/{month}
 ├─ GET /regional/overview/{month}
 └─ GET /smart/anomaly-timeline          ← مرة واحدة فقط
```

المذكّرة الخلفية (`_get_smart_data`) تخزّن `smart_overview_{month}` لمدة 5 دقائق، لذا المكرر غير مكلف خلفياً لكنه مهدر على الشبكة ويجب إزالته من الواجهة.

## 4. مقترح تبسيط الواجهة (التصميم الجديد)

### 4.1 المبدأ: «قرار أولاً، تحليل ثانياً»
أعد ترتيب الصفحة على مبدأ التدرج التدريجي (Progressive Disclosure) بثلاث طبقات:

```
الطبقة 1 — لوحة القرار (تُرى فوراً، بدون تمرير)
  ├─ شريط تحكم مصغّر (شهر + مستشفى فقط)
  ├─ حالة الشهر (بطاقة واحدة)
  ├─ قائمة الأولويات: المستشفيات الحرجة + الإنذار المبكر (إن وُجد)
  └─ زر «تحليل كامل» يفتح باقي الصفحة
الطبقة 2 — تحليل الشهر (أقسام قابلة للطي، معظمها مطوي)
  ├─ المستشفيات: جدول الشذوذ + مستشفيات سليمة
  ├─ الجغرافيا والإقليم: خريطة + إقليمي
  └─ نماذج متقدمة: XGBoost، SHAP، عنقودات، ارتباط، بواقي، أنماط، Lead-Lag
الطبقة 3 — عند الطلب
  ├─ مودال «المنهجية» (نص واحد موحّد بدل 6 تكرارات)
  └─ التقرير الشامل + التصدير (كما هو)
```

**التفاصيل:**
1. **أغلق قسم «كيف تُحسب» افتراضياً** أو انقله إلى مودال واحد «المنهجية» يُفتح من أيقونة ⓘ في رأس الصفحة، واحذف صناديق «كيف تم تحديد» المكررة من المودالات (أو اختصرها لسطر tooltip واحد).
2. **أدرج الأقسام الشرطية داخلياً**: اجعل الإنذار المبكر جزءاً من «لوحة القرار»، وXGBoost/المحافظات/الإقليمي أقساماً مطوية داخل «نماذج متقدمة» تُفتح فقط عند الحاجة.
3. **وحّد منسّق المؤشر**: قائمة واحدة «المؤشر: [قيصرية/مضاعفات/وفيات]» تطبَّق على البواقي والأهمية والطبقية معاً (اختيار واحد يحدّث الثلاثة) — أو اجعل لكل رسم خياراته الخاصة داخل بطاقته فقط عند الحاجة.
4. **دمج رؤى الشذوذ**: بطاقة KPI 1 تعرض الرقم فقط، والدونات والهيستوجرام والجدول كلها تصف نفس التوزيع ⇒ يُبقي على الجدول + الهيستوجرام، ويُنقل الدونات للمودال أو يُحذف.
5. **دمج رؤى SHAP**: بطاقة KPI 3 + «أهمية العوامل» + Global FI تكرر نفس المعلومات ⇒ رأس واحد موحّد «العوامل الأكثر تأثيراً» يُرسم مرة واحدة، والبطاقة تشير إليه.
6. **تجميع الرسوم المزدحمة في تبويبات داخلية**: قسم «نماذج متقدمة» يتحول إلى 3–4 تبويبات صغيرة (عنقودات / ارتباط وبواقي / أنماط وLead-Lag) بحيث لا تُعرض سوى مجموعة واحدة من الرسوم في كل مرة — هذا وحده يقلل الرسوم المتزامنة من ~17 إلى ~5.
7. **لغة أبسط للمستخدم النهائي**: ضع المصطلحات التقنية (SHAP، XGBoost، Apriori) بين قوسين بعد العبارة العربية إن لزم، وليست عنواناً رئيسياً.

### 4.2 تحسينات الأداء (لازمة لأي إعادة تصميم)
1. **إزالة الطلب المكرر**: `updateHospitalList` يقرأ `smartCurrentData.data.anomalies` (المحمّل أصلاً) بدل إعادة الجلب، أو يستقبل الحمولة كمعامل.
2. **Lazy rendering بـ IntersectionObserver**: لا تُرسم الرسوم إلا عند اقترابها من مجال الرؤية؛ عند طي قسم تُستبدل `Plotly.purge` لتخليص الذاكرة.
3. **استبدال setTimeout بتسلسل حقيقي**: ارسم في ترتيب واحد متزامن (الرسوم الرئيسية أولاً ثم البقية في `requestIdleCallback`)، أو فعّل الرسم بالترتيب اعتماداً على رؤية القسم.
4. **تأجيل الخط الزمني**: لا تُبنَ إطارات الحركة إلا عند أول ظهور للقسم (لأنه الأثقل).
5. **تخفيض ارتفاع الرسوم الافتراضي** (320–460px) إلى 260px مع تمكين التكبير عند الحاجة، لتقليل مساحة DOM.

### 4.3 الصيانة والاتساق
1. **استخراج الأنماط**: نقل كل الأنماط inline في HTML وجافاسكربت إلى فئات CSS (`styles.css`): بطاقات، شبكات متجاوبة، شارات، جداول. ثم اعتماد الشبكات المتجاوبة `repeat(auto-fit,minmax(...))` بدل `repeat(4,1fr)` الثابت.
2. **تقسيم `smart-analytics.js`** إلى وحدات منطقية: `smart/kpi.js`, `smart/charts.js`, `smart/regional.js`, `smart/report.js`… (أو على الأقل فئات/كائنات).
3. **إصلاح الأخطاء النصية** والأوصاف المتناقضة (منهجية مودال المستشفى مقابل المنهجية العامة)، وحذف دالة `_smartEscapeHtml` المكررة.
4. **أساسية الوصول**: `role="dialog"` + Escape للمودالات، `aria-label` للأزرار، تحسين التباين، حجم خط أدنى 0.75rem.

## 5. خارطة طريق التطوير المقترحة

| المرحلة | المحتوى | الجهد |
|---------|---------|-------|
| **A — تنظيف سريع (بدون تغيير تصميم)** | إزالة الطلب المكرر، طي المنهجية افتراضياً، إصلاح الأخطاء النصية، حذف الدالة المكررة | نصف يوم |
| **B — الأداء** | IntersectionObserver + Lazy render + استبدال setTimeout + تأجيل الخط الزمني | 1–2 يوم |
| **C — الهيكلة الجديدة** | لوحة القرار أعلى الصفحة + أقسام مطوية + تبويبات «نماذج متقدمة» + توحيد المنسّقات ودمج رؤى SHAP/الشذوذ | 2–3 أيام |
| **D — الصيانة والجودة** | نقل الأنماط إلى CSS متجاوب، تقسيم الملف، تحسين الوصول، توحيد نصوص المنهجية | 2–3 أيام |

**توصية:** البدء بـ A+B (مكسب فوري بتكلفة منخفضة)، ثم C (التحويل الأكبر في تجربة المستخدم)، ثم D بالتوازي.

## 6. ملاحظات تطويرية إضافية

- **نهاية `/smart/overview/{month}`** تعيد كل شيء في حمولة واحدة — ممتاز للتصميم الجديد (لا حاجة لتغيير عقد API)، ويمكن لاحقاً دمج `governorate-analysis` و`regional/overview` اختيارياً في نفس الحمولة لتقليل الجولات.
- **التبويب مُحمّل كسولاً** (`data-src="/static/tabs/smart-analytics.html"`) — الاستفادة من ذلك بعدم رسم أي شيء حتى يُفتح التبويب فعلياً.
- **وضع اللغة الإنجليزية** موجود للتقرير فقط؛ يمكن تعميمه على الشاشة كاملة لاحقاً (العناوين والقوائم موجودة في `i18n.js`).
- المشروع يستخدم Plotly.js فقط في هذه الشاشة — أي رسوم جديدة يجب أن تلتزم به (لا مكتبات إضافية).
