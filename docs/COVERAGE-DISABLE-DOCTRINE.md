# عقيدة «المغطى بالمجموع / المعطّل» — قاعدة إلزامية عند التعامل مع المؤشرات

> **حالة القاعدة:** إلزامية لكل من يطور على هذا المشروع (وكذلك أي مساعد AI).
> أي كود جديد يلمس **اكتمال البيانات (Completeness)** أو **قوائم المؤشرات
> المفقودة** أو **نافذة «لماذا؟» (Why popup)** أو **شاشة التدقيق (Audit)**
> يجب أن يطبّق هذه العقيدة — وإلا سيعود التناقض الذي أصلحناه: نافذة «لماذا؟»
> تعلّم مؤشراً «مفقوداً» بينما حساب الاكتمال في نفس النافذة يسامحه. حدث هذا
> فعلاً مرتين (2.n ثم 6.g لمستشفى الخير / 2026-02).
>
> اختبار الحماية: `tests/test_ui_doctrine_docs.py`

---

## 1. القاعدة الإلزامية (اقرأها قبل أي تعديل)

**مؤشر له صف بقيمة `None` في `indicator_values` ≠ مؤشر مفقود.**

قبل تعليم أي مؤشر «مفقوداً» — في أي شاشة أو تقرير أو API — يجب تمريره عبر
بوابة الغطاء:

1. **مغطى بمجموع (covered by total):** عدم وروده مفسَّر بقاعدة مجموع
   (انظر §2) → ليس مشكلة، ولا يُعاقَب عليه الاكتمال، ولا يظهر في قوائم
   «المفقودون».
2. **معطّل (disabled):** المستخدم عطّله من **شجرة المؤشرات** (Indicator Tree)
   — لكل مستشفى (`hospital_indicator_configs`) أو افتراضياً لشهر معيّن
   (`indicator_default_configs`) → ليس مشكلة أيضاً.
3. **فجوة حقيقية (real gap):** لم يُغطَّ ولم يُعطَّل → هذه وحدها مشكلة بيانات،
   وحدها تُنزل الاكتمال.

```
مفقود ظاهرياً = مغطى؟ أو معطّل؟ → ليس مشكلة
              └→ غير ذلك      → فجوة حقيقية (تعليم + خصم اكتمال)
```

## 2. مصدر الحقيقة: دالة واحدة لا تُكرَّر

```python
from app.engine.quality.rules import compute_covered_codes

covered = compute_covered_codes(values, disabled_codes, db)
# values        = {code: value} للقيم الموجودة فقط (value is not None)
# disabled_codes= رموز المؤشرات المعطّلة للمستشفى/الشهر
# db            = مرّر الجلسة دائماً حتى تُقرأ القواعد من قاعدة البيانات
```

- **لا تُعد كتابة منطق التغطية** في أي مكان آخر. لو احتجت سلوكاً مختلفاً
  فوسّع هذه الدالة وحدّث الاختبارات.
- **مرّر `db` دائماً.** بدونها تسقط الدالة إلى عائلات القواعد المترجمة
  (SUM_RULE_SPECS) وقد تفوّت قواعد المستخدم (كان هذا سبب خلل 6.g).

### عقيدتا التغطية داخل `compute_covered_codes`

| نوع القاعدة | أمثلة حقيقية | متى يُغطَّى الابن غير المُبلَّغ؟ |
|---|---|---|
| **حصرية** `eq` / `le_sum` | `2 = 2.c+...+2.j`، `2 = 2.a+2.b`، `6 = 6.a+6.b+6.c` | فقط عندما يساوي مجموع الأبناء **المُبلَّغين** الأصل ضمن التسامح — حينها أي ابن ناقص «مفسَّر» بالباقي |
| **احتوائية** `gt` / `ge` / `ge_factor` | R080: `6 > 6.d+6.f+6.g`، R001: `2 >= 3+4+5` | عندما يكون الأصل مُبلَّغاً والأبناء المُبلَّغون **لا يتجاوزونه** — الفئات غير المُبلَّغة تعني «لا نشاط في هذه الفئة» (حالة مشروعة). إذا تجاوز الأبناء المُبلَّغون الأصل → **لا تغطية** (الغياب قد يكون سبب عدم التطابق) |

## 3. التعطيل من شجرة المؤشرات — حيث يُقرأ

عند حساب «المؤشرات المطلوبة» لشهر مستشفى، استبعد دائماً:

1. `hospital_indicator_configs` حيث `is_enabled = false` (تعطيل لكل مستشفى
   ويدوم — يتغلب على الافتراضي).
2. `indicator_default_configs` حيث `is_enabled = false` لذلك **الشهر** —
   ما لم يوجد تجاوز صريح لذلك المستشفى في (1).
3. الإعداد `auto_disable_null_indicators` في `system_settings`: إذا كان
   `"true"` فكل مؤشر بلا قيمة يُعامل كمعطّل تلقائياً.

**التنفيذ المرجعي الكامل:** `_recalc_completeness` في `app/api/dashboard.py`
(الخطوات 4/4b/5/6: `manual_map`، `default_map`، `override_map`، `_dis()`).
لا تكرَّرها — استوردها أو اقلّد بنيتها بالضبط.

## 4. المواضع التي تطبّق العقيدة اليوم (حتى لا تكسرها)

| الموضع | الاستخدام |
|---|---|
| `app/api/dashboard.py::_recalc_completeness` | إعادة حساب الاكتمال (مغطى + معطّل خارج المقام) |
| `app/engine/audit/explain.py::find_data_problems(values, db)` | قائمة «مشاكل البيانات» في نافذة «لماذا؟» وشاشة التدقيق — **مرّر `db`** |
| `app/engine/quality/rules.py::get_covered_child_codes` | أثناء تنفيذ قواعد التحقق نفسها |
| تفصيل الاكتمال في `component-diagnostics` | قائمة «المفقودون» يجب أن تستثني المغطى والمعطّل |

**قاعدة ذهبية:** أي استعلام جديد يعدّ «المؤشرات المطلوبة» أو «المفقودة» يجب أن
يستثني: (المغطى عبر `compute_covered_codes`) + (المعطّل عبر §3).

## 8. المؤشرات الشكلية (synthetic) — ما هي وما ليست

**`SYNTHETIC_INDICATOR_CODES = {"0"}`** («Main elements complete ratio»)
هي التسمية الشكلية **الوحيدة** حتى الآن: ترويسة من نموذج SRMNH ليست مؤشر
بيانات — صفر صفوف قيم، لا قاعدة تحقق تشير إليها، لا أبناء. تُخفى من شجرة
المؤشرات (`build_tree_from_db` / `get_flat_list_from_db`) ومن كل المحركات.**تنبيه ضد الإفراط في الإخفاء:** تدقيق 2026-09 وجد 8 مؤشرات أخرى بلا صفوف قيم حتى الآن — `2.k`، `2.l`، `11.a`، `11.b`، `12`، `16`، `21`، `26` — لكنها
**مؤشرات حقيقية نادرة الحدوث** (وفيات، إحالات، ICU، تسجيل مكرر...) وليست
شكلية: كلها ضمن شجرة النموذج الأصلية، قواعد تحقق تشير إليها (`R004`،
`R073`، `R048`...)، وبعضها له صفوف إعداد مستشفيات. **لا تضفها للقائمة** —
إخفاؤها سيخفي فجوات رفع حقيقية.

**المسار المعتمد لإسكاتها:** بدل إضافتها للقائمة الشكلية، استخدم زر
«غير المُبلَّغ عنها إطلاقاً» في تبويب شجرة المؤشرات (`POST
/hospitals/indicators/disable-never-reported`). يعطّل عبر
`hospital_indicator_configs` كل مؤشر فعّال بلا صفوف قيم في كامل التاريخ
لجميع المستشفيات دفعة واحدة — أي عقيدة §3 (المعطّل) لا §8 (الشكلي) — فلا
يُحتسب ناقصاً ولا يُنزل الاكتمال، ويعود للعمل فوراً لو أعاد مستشفى ما رفعه
(مجرد إعادة تفعيله من الشجرة). تُستثنى الرموز الشكلية دائماً. اختبار الحماية:
`tests/test_never_reported_indicators.py`.

**معيار إضافة مؤشر لقائمة الشكلية (يجب استيفاؤه كله):**
1. صفر صفوف `indicator_values` عبر كل التاريخ.
2. لا قاعدة تحقق مفعّلة تشير إلى رمزه في `params`.
3. ليس أباً لأي مؤشر آخر.
4. غيابه من نموذج الرفع نفسه (ترويسة/مجموع لا يرفعه المستشفى).

الأداة المرجعية للتدقيق المستقبلي: استعلم بالعدّ حسب `indicator_id` في
`indicator_values` + `Rule.params LIKE` + `Indicator.parent_id` — ثم راجع
يدوياً قبل أي إضافة. اختبار الحماية: `tests/test_tree_hides_synthetic_zero.py`
(يثبت أن الرمز «0» وحده مخفي وأن المؤشرات الحقيقية الثمانية ما زالت ظاهرة).
