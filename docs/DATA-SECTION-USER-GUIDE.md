# دليل المستخدم لقسم البيانات — نظام HEALTH AI – SRMNH

تقرير تقني يوثّق بناء «دليل المستخدم» داخل التطبيق: الجرد الفعلي لشاشات قسم
البيانات، بنية ملفات الأدلة، طريقة التنقّل، الصور الملتقطة، وما تم التحقق منه
وما لم يُتحقق.

---

## 1. الغرض والنطاق

الهدف: أن يجد كل مستخدم — إداريًا أو فنيًا — شرحًا مستقلًا لكل شاشة في قسم
البيانات: ما الغرض منها، ما عناصرها، كيف تُستخدم خطوة بخطوة، ماذا تعني الحقول
والأزرار، وكيف تُقرأ النتائج.

قيود التزمنا بها:

- لم يُعدَّل أي منطق عمل، ولا أي API، ولا مخطط قاعدة البيانات، ولا محرك حساب أو
  سياسة تحليلية.
- لم يُختَرع أي حقل أو زر: كل عنصر موثّق موجود في الشاشة الفعلية، وكل رقم في
  الأمثلة مأخوذ من بيانات النظام الحالية.
- كل شاشة لها دليلها المستقل؛ لا شرح عام واحد يغطي الجميع.

## 2. الجرد الفعلي لشاشات قسم البيانات

الجرد أُخذ من قائمة التطبيق الحيّة (`GET /api/menu`) ومن تسجيل التبويبات في
`app/menu_registry.py`، ثم قُرئت لكل شاشة واجهتها (`static/tabs/*.html`)،
وسكربتاتها، ونقاط النهاية التي تستدعيها، والصلاحيات المفروضة على الخادم.

| # | الشاشة | الموقع في القائمة الحيّة | مفتاح التبويب | الصلاحية | السؤال الذي تجيب عنه |
|---|--------|---------------------------|----------------|-----------|----------------------|
| 1 | Upload Data — رفع البيانات | Data | `upload` | `data.upload` | كيف أرفع ملف الشهر وأتابع التحليل حتى النتيجة؟ |
| 2 | Data Tree — شجرة البيانات | Data | `indicator-tree` | `settings.read` | ما قيم مستشفى في شهر معيّن، مؤشرًا مؤشرًا، وما المفقود منها؟ |
| 3 | Data Group — مجموعة البيانات | Data | `indicator-groups` | `settings.read` | كيف أُفعّل/أُعطّل مجموعة مؤشرات كاملة وأرى أثرها؟ |
| 4 | Indicators — المؤشرات | Data | `indicators` | `settings.read` | كيف أُنشئ مؤشرًا محسوبًا وأعدّل صيغته؟ |
| 5 | Validation Rules — قواعد التحقق | Data | `rules-manager` | `rules.read` (والكتابة `rules.write`) | كيف أضبط قواعد فحص البيانات وأختبرها وأرى تاريخها؟ |
| 6 | Direction Coverage — تغطية الاتجاه | Analysis (في قاعدة البيانات الحالية) | `direction-coverage` | `settings.read` (و`/apply` بـ`settings.write`) | ما المؤشرات بلا اتجاه محدد، وما الاتجاه المقترح لها؟ |

### ملاحظة على موقع «تغطية الاتجاه»

`DEFAULT_GROUPS` في `app/menu_registry.py` يضع `direction-coverage` داخل مجموعة
**Data**، لكن صفوف القائمة المحفوظة في قاعدة البيانات أُنشئت قبل ذلك، فبقيت
الشاشة معروضة تحت **Analysis**. الشاشة موثّقة ضمن هذا الدليل لأنها من عائلة
البيانات (تعريف المؤشرات واتجاهها)، ودليلها يذكر موقعها الفعلي في القائمة حتى
لا يبحث عنها المستخدم في المكان الخطأ.

المجموعات الأخرى في القائمة (Quality/Oversight، Analysis، Added Value، System،
Guides) خارج نطاق هذه المهمة ولم تُوثّق هنا.

## 3. بنية نظام الدليل

النظام ثابت (static) بالكامل، على نمط بقية التطبيق: ملف محتوى لكل شاشة + مكوّن
عرض واحد + تبويب مستقل.

```
static/js/guide-kit.js          نصوص مشتركة + ترتيب الأقسام A–I وعناوينها
static/js/guides/upload.js              دليل رفع البيانات
static/js/guides/data-tree.js           دليل شجرة البيانات
static/js/guides/data-groups.js         دليل مجموعة البيانات
static/js/guides/indicators.js          دليل المؤشرات
static/js/guides/rules.js               دليل قواعد التحقق
static/js/guides/direction-coverage.js  دليل تغطية الاتجاه
static/js/guide-data.js         ترتيب الأدلة + البحث بالمفتاح
static/js/user-guide.js         الفهرس + البحث + صفحة الدليل + التنقّل
static/tabs/user-guide.html     هيكل التبويب وأنماطه (.ug-*)
static/guides/img/*.png         لقطات الشاشات الفعلية
```

كل ملف دليل يصدّر كائنًا واحدًا بالشكل:

| الحقل | المعنى |
|-------|--------|
| `key` | مفتاح الشاشة، ويطابق `data-tab` في التطبيق |
| `tab` | التبويب الذي يفتحه زر «افتح هذه الشاشة» |
| `permission` | الصلاحية المفروضة على الخادم لهذه الشاشة |
| `title` / `menu` | الاسم ومسار القائمة، بالعربية والإنجليزية |
| `icon` | أيقونة الشاشة كما في القائمة |
| `shot` / `shotAlt` / `shotLegend` | اسم اللقطة، نصها البديل، وقائمة الشرح المرقّمة |
| `sections` | الأقسام التسعة `overview, layout, usage, fields, actions, results, examples, problems, related` |

بنية الأقسام التسعة (A–I) موحّدة في `guide-kit.js`، فلا يختلف شكل دليل عن آخر.

### دعم اللغتين وRTL

- كل نص في ملفات الأدلة مزدوج: `{ en, ar }`، ويُختار عند العرض حسب `lang` في
  `localStorage` (نفس مفتاح i18n المستخدم في التطبيق).
- عند تبديل اللغة يُعاد رسم الدليل عبر `MutationObserver` على `dir`/`lang`،
  وتُعاد تعبئة التبويب عند تبديل التبويبات عبر `window.applyLang`.
- التخطيط يتبع `dir` تلقائيًا (لا أنماط LTR مثبّتة داخل `.ug-*`).

### التكامل مع التطبيق

| الملف | التغيير |
|-------|---------|
| `app/menu_registry.py` | تبويب `user-guide` (📖، صلاحية `dashboard.read`) + إدراجه في مجموعة System |
| `static/index.html` | `<div id="tab-user-guide" data-src="/static/tabs/user-guide.html">` |
| `static/js/app.js` | `import('./user-guide.js')` + `case 'userGuide'` |
| `static/js/main.js` | `initUserGuide` عند أول فتح، وعنوان/أيقونة التبويب، وإدراجه في البحث الشامل؛ والحفاظ على `#hash` عند الإقلاع من رابط عميق |
| `static/js/i18n.js` | مفاتيح: `User Guide`, وصف التبويب، ونص حقل البحث |
| `static/js/renderSidebar.js` | قائمة فرعية تحت عنصر **User Guide**: «كل الأدلة» + دليل لكل شاشة، تُفتح مباشرة |
| `static/css/styles.css` | أنماط `.sidebar-subitems` / `.sidebar-subitem` (بما فيها RTL والوضع المطوي) |
| `static/tabs/user-guide.html` | الهيكل والأنماط |
| `tests/test_data_guides_documentation.py` | اختبار جرد يمنع نقص دليل أو لقطة |

### التنقّل

- `#guide` — فهرس قسم البيانات (بطاقات + بحث + عدّاد «موثّق/الإجمالي»).
- `#guide/data/<key>` — صفحة دليل مستقلة، قابلة للحفظ والمشاركة والتحديث.
- داخل الصفحة: مسار تنقّل (الفهرس ← قسم البيانات ← الشاشة)، فهرس محتويات
  للأقسام التسعة، زر «افتح هذه الشاشة»، ثم شريط «السابق / كل أدلة البيانات /
  التالي».
- البحث يطابق أولًا أسماء الشاشات بالعربية والإنجليزية، ثم يعود إلى النص الكامل
  إن لم يطابق أي اسم.
- من الشريط الجانبي: عنصر **User Guide** (System) يعرض قائمة فرعية فيها «كل
  أدلة البيانات» ثم دليل لكل شاشة؛ اختيار أي منها يفتح تبويب User Guide على
  ذلك الدليل مباشرة، ويظل العنصر مُبرزًا ما دام الدليل مفتوحًا، ويتغيّر اسمه مع
  تبديل اللغة. (عنصر **Guides** يبقى فهرسًا مستقلًا بلا قائمة فرعية.)

## 4. الصور

التُقطت من التطبيق العامل على `http://127.0.0.1:9090` بعد تسجيل دخول إداري،
بدقة عرض 1440×1000، وكل لقطة تُظهر الشاشة بحالتها الطبيعية مع بيانات النظام
الفعلية:

| الشاشة | الملف |
|--------|-------|
| Upload Data | `static/guides/img/upload-data.png` |
| Data Tree (مستشفى الصليب الأحمر الميداني ICRC — 2026-10) | `static/guides/img/data-tree.png` |
| Data Group | `static/guides/img/data-groups.png` |
| Indicators | `static/guides/img/indicators.png` |
| Validation Rules | `static/guides/img/validation-rules.png` |
| Direction Coverage | `static/guides/img/direction-coverage.png` |
| صفحة الدليل نفسها (مثال) | `static/guides/img/guide-page-example.png` |

الشرح المرقّم يُعرض كقائمة مرجعية أسفل كل صورة (`shotLegend`) بدل رسم دوائر فوق
الصورة، لأن الرسم فوق اللقطة يفقد موضعه عند تغيّر التخطيط أو اللغة.

**حدّ معروف:** في اللقطات شارة صغيرة أعلى اليسار من أداة المتصفح المستخدمة في
التقاطها؛ هي أثر أداة التصوير وليست جزءًا من التطبيق.

## 5. التحقق

### ما تم تشغيله

| الفحص | النتيجة |
|-------|---------|
| `pytest tests/test_data_guides_documentation.py tests/test_guides_tab.py` | 14 نجحت (منها 7 لهذا النظام) |
| `node --check` على `guide-kit.js`, `guide-data.js`, `user-guide.js`, ملفات `guides/*.js`, `main.js`, `app.js`, `i18n.js` | نجح |
| فتح التبويب من القائمة | يظهر «User Guide» تحت System ويُحمّل الفهرس بـ6 بطاقات |
| رابط عميق `?screen=user-guide#guide/data/upload` | يفتح دليل رفع البيانات مباشرة بعد إعادة التحميل |
| التنقّل: مسار، فهرس محتويات، سابق/تالي/فهرس | يظهر ويعمل في الدليل المفتوح |
| زر «افتح هذه الشاشة» | ينقل إلى تبويب `upload` ويحدّث `?screen=upload` |
| القائمة الفرعية تحت User Guide | «كل أدلة البيانات» + الأدلة الستة، بأسماء عربية ثم إنجليزية بعد تبديل اللغة |
| فتح دليل من القائمة الفرعية | يفتح تبويب User Guide على الدليل نفسه (`#guide/data/<key>`)، ويُبرز العنصر المفتوح |
| البحث (عربي/إنجليزي) | «شجرة» → دليل واحد، «قواعد» → دليل واحد، «rules» → دليل واحد، والبحث النصي «مستشفى» يعود إلى 5 أدلة |
| العربية/RTL | `dir=rtl`، المسار والفهرس والأقسام وشارة الصلاحية وقائمة الصور كلها بالعربية |
| الصور داخل الأدلة | تُحمّل بالأبعاد الكاملة (1440×1000) |

### ما لم يُتحقق

- لم يُنقر كل زر في كل شاشة موثّقة للتحقق من رسائل الأخطاء الفعلية؛ أوصاف
  الأزرار مأخوذة من قراءة الكود ومن حالات ظاهرة في الواجهة، لا من تجربة كل مسار.
- لم تُجرَّب حالات فشل الرفع (ملف تالف/أكبر من 20MB) تجربةً فعلية.
- لم تُختبر الشاشات بصلاحيات محدودة (مستخدم بلا `settings.write` مثلًا)؛
  الصلاحيات المذكورة في الأدلة مأخوذة من تزيين نقاط النهاية في الخادم.
- لم تُراجع وصياغة الأدلة لغويًا من قِبل مستخدم نهائي.

## 6. الصيانة

عند إضافة شاشة جديدة إلى قسم البيانات:

1. أضف التبويب إلى `TAB_REGISTRY` وإلى مجموعة Data في `DEFAULT_GROUPS`.
2. أنشئ `static/js/guides/<screen>.js` بالحقول أعلاه وضع `key` = `tab` = مفتاح الشاشة.
3. أضف استيراده إلى `DATA_GUIDES` في `guide-data.js` (فيظهر تلقائيًا في الفهرس
   وفي القائمة الفرعية تحت User Guide).
4. التقط لقطة حديثة وضعها في `static/guides/img/` وحدّث `shot` و`shotLegend`.

`tests/test_data_guides_documentation.py` يفشل تلقائيًا إذا بقي عنصر في مجموعة
Data بلا دليل، أو وُجد دليل لتبويب غير مسجّل، أو اختلفت الصلاحية الموثّقة عن
صلاحية التبويب، أو أشار دليل إلى صورة غير موجودة.
